# Obsidian + WorkBuddy 第二大脑方法论（完整版）

> 来源：飞书文档《obsidian+workbuddy完整搭建流程》 https://ccnope4jr4h4.feishu.cn/wiki/O5mzw2XvoicuGIkuZdTcSeZan3f
> （正文需登录查看，本文件内容来自该文档的公开转载版本，2026-10-18 整理归档）

## 一句话总结

把 Obsidian 当长期记忆体，WorkBuddy 当执行引擎，飞书当数据源——三者打通后，AI 每次开口都"懂你的业务"，不再是从零开始的陌生人。

分工逻辑：

```
人        → 负责判断和决策
Obsidian  → 负责长期沉淀和结构化
WorkBuddy → 负责读取、整理、提炼和执行
```

## 二、整体架构：8 + 4 层结构

### 工作域（8 层）

```
00_首页.md          ← 作战室入口（风险看板 + 快速导航）
01_系统层/          ← 给 AI 看的底层规则
02_收集箱/          ← 所有待处理资料的入口
03_项目层/          ← 平台运营 / 大促战役 / 新渠道 / 供应链协同
04_知识资产/        ← 平台行业 / 食品供应链 / 增长方法论 / SOP / 经营口径
05_技术成果库/      ← Agent / 脚本 / 工作流
06_组织与人/        ← 团队网络 + 外部关系
07_过程记录/        ← 周报月报 / 会议纪要 / 复盘
08_归档/            ← 已结束、仅需追溯的内容
```

### 全维度（+3）

```
20_生活/            ← 健康 / 家庭 / 人际
30_爱好/            ← 健身 / 音乐 / 历史 / AI
40_投资/            ← 股票 / 基金 / 黄金
```

### 设计原则

1. **收集箱必须清空**——不能长期堆积
2. **知识资产要提炼**——不要直接堆原文
3. **敏感数据绝不入库**——密码 / Token / 隐私信息

## 三、核心机制：让 AI 每次都"懂你"

在 `01_系统层/` 下放几个特殊文件，WorkBuddy 每次启动时**默认先读这些文件**，再处理任务。

### 3.1 WorkBuddy 启动协议

作用：让 AI 知道"先读背景再干活"，而不是每次都从零开始猜需求。

```markdown
# WorkBuddy 启动协议

> 除非用户明确说「这次不用第二大脑」，否则凡涉及以下任务，
> WorkBuddy 默认先读取本 vault：

- 工作 / 项目推进
- 知识整理 / 会议纪要提炼
- 飞书资料处理
- Agent / 工作流 / 自动化
- 经营分析 / 复盘

每次启动默认动作：
1. 读 01_系统层 了解用户与规则
2. 读相关项目页 / 知识资产获取背景
3. 再处理具体任务
```

### 3.2 业务全景文件

给 AI 看的"我在什么盘子里做事"，包含：

- 我是谁、负责什么品牌、团队多大
- 核心产品线和货盘规模
- 获客链路和客户运营阶段
- 团队结构和关键人员
- KPI 口径（GMV / 毛利率 / 复购率 / LTV / 人效）
- 跨部门协作关系
- 数据源地图（哪些数据在飞书哪个 Base 里）

**效果**：跟 WorkBuddy 说"帮我分析本月毛利率"，它已经知道口径怎么算、数据在哪个表里、上个月是多少。

### 3.3 协作规则

```markdown
# 协作规则

1. 入口唯一：不确定的资料先放收集箱，不要求我一开始就分类
2. AI 先判断：整理、分类、提炼、归档优先由 WorkBuddy 做，我只确认
3. 不重复搬运：飞书原文保留在源头，Obsidian 只存提炼后的长期价值
4. 确认机制：涉及删除、对外发送、关键决策，先问我
5. 可追溯：进入知识资产的内容要写明来源链接
```

## 四、飞书文档批量归档：从 196 篇到 8 张知识卡片

投入产出比最高的一步。

### 4.1 扫描阶段

对 WorkBuddy 说：

> "扫描我飞书云文档中近半年修改或创建的文档，排除 Base/多维表格，只处理 docx/sheet/slides 类型。按我的 Obsidian 八层结构分类，生成一份扫描总览。"

WorkBuddy 通过 lark-cli 工具链完成：

1. **遍历飞书空间**（我的文档库 / 公司制度 / 新人课堂 / 数据侧 / 重要通知 / 客服知识库等）
2. **过滤类型**：跳过 Base/多维表格，只取 docx / sheet / slides
3. **提取正文**：对 docx 类型文档提取全文内容
4. **生成总览**：每篇文档记录标题、来源空间、编辑时间、类型、一句话摘要

**关键设计**：每篇文档都带 `obj_token`（飞书文档 ID），需要看原文时在飞书客户端搜索即可定位。**Obsidian 里不堆原文，只存摘要和索引。**

### 4.2 主题合并提炼

同一主题的多篇文档合并成一张知识卡片，只保留长期价值：

```markdown
# 客户生命周期与 ABCD 分级 SOP

## 一句话结论
> 把「线索→成品客户」拆成 6 个阶段 + ABCD 四级运营动作，
> A 类 12 小时触达、14 天转化；N 类直接过滤。

## 核心要点
### 客户 6 阶段
1. 潜在客群 → 2. 线索 → 3. 样品客户 →
4. 成品客户 → 5. 沉默客户(60天) → 6. 丢失客户

### ABCD 分级矩阵
- A 类（高价值）：12h 触达，14 天转化
- B 类：体验官 1v1 跟进
- C 类：1 粘性品 + 1 扩品组合
- D 类：标准化培育
- N 类（商贸/团餐）：过滤不计入

## 来源 / 原文
- 线上客户运营 `LnZpdo8SvoWEtZxVUozcDGPRntN`
- 新客快速识别话术 `D7LrdVIcYo3dKAxoVNEckVRhnob`
```

**最终结果**：196 篇飞书文档 → 1 份全量 MOC 索引 + 8 张主题合并的知识卡片。信息密度高，查找快，不膨胀。

### 4.3 归档策略

每张卡片头部带 frontmatter，记录来源、提炼日期、标签，方便后续检索和回溯。

## 五、日常运转：收集箱工作流

### 5.1 每日节奏

| 时机 | 动作 | 谁做 |
|------|------|------|
| 随时 | 资料/链接/截图丢进 `02_收集箱` | 我 |
| 每天 | 对 WorkBuddy 说"帮我整理今天的收集箱" | AI 辅助 |
| 下班前 | 确认收集箱已清空 | 我 |
| 每周 | 沉淀 1-3 条知识资产 | 我 + AI |
| 每月 | 清理项目、归档旧资料 | AI 辅助，我确认 |

### 5.2 实际对话示例

**场景 1：收到一份竞品分析文档**

我：飞书里新出了一份竞品价格对比，帮我扫描进来，归到知识资产。

WorkBuddy：
1. 通过 lark-cli 读取飞书文档正文
2. 提炼核心数据（价格带 / 差异点 / 竞品货盘）
3. 与已有的 `竞品价格对比分析.md` 合并（而不是新建一篇）
4. 更新扫描总览中的索引
5. 问我：已合并到 `04_知识资产/平台与行业知识/竞品价格对比分析.md`，要不要看 diff？

**场景 2：月度经营复盘**

我：帮我做 7 月线上业务复盘。

WorkBuddy：
1. 读取 `01_系统层/业务全景.md` → 知道 KPI 口径
2. 读取 `07_过程记录/` 上几份月报 → 知道趋势
3. 读取 `04_知识资产/经营分析口径/` → 知道怎么算
4. 基于以上背景，帮我搭复盘框架，我填数据

## 七、踩过的坑和经验总结

### 坑 1：一开始就想把所有东西都搬进 Obsidian
错误：把飞书原文一篇一篇复制进来，笔记膨胀到几百篇，根本没法用。
正确：Obsidian 只存**提炼后的长期价值**。原文留在飞书，Obsidian 里放摘要 + 来源链接。

### 坑 2：分类太细，维护成本高
错误：一开始就建了 20 多个子目录，每篇笔记纠结放哪个。
正确：8 个一级目录够用。不确定的先扔收集箱，让 AI 帮你判断分类。**入口唯一，分类延迟。**

### 坑 3：系统层文件写得太抽象
错误：业务全景写成了公司介绍，AI 读完还是不知道你要什么。
正确：写**给 AI 看的**，不是写给人看的。重点写：口径定义、数据源位置、协作关系、注意事项。越具体越好。

### 坑 4：飞书 Base 混在扫描结果里
错误：扫描飞书文档时没过滤类型，Base/多维表格也被拉进来，正文提取失败还占空间。
正确：明确指定只处理 docx / sheet / slides，跳过 Base。

### 坑 5：知识卡片没有写来源
错误：提炼完知识卡片，没记录来源文档 ID，过几个月想看原文找不到。
正确：每张知识卡片底部必须有 `## 来源 / 原文` 段落，记录飞书文档 ID（obj_token），保证可追溯。

## 十、适合谁

- **业务管理者**：手下管多个项目/平台，信息来源多，需要 AI 懂你的业务背景
- **知识工作者**：大量文档/数据/会议纪要需要结构化沉淀
- **团队负责人**：需要把个人经验变成可传承的组织资产
- **飞书重度用户**：云文档越来越多，但找不到、用不起来

**核心就一句话**：不要让 AI 每次都从零开始。给它一个结构化的记忆体，它的每一次输出都带着你的业务上下文——这才叫"AI 搭档"，不是"AI 问答机器"。
